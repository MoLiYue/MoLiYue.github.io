ECMP路由

Created2026-04-29|Updated2026-06-02
|Word Count:860|Reading Time:3mins

ecmp路由是什么

ECMP 路由全称是 Equal-Cost Multi-Path Routing，中文一般叫 等价多路径路由。

它的意思是：

到同一个目的网段，如果有多条“代价相同”的路径，路由器/交换机可以同时使用这些路径转发流量，而不是只选一条。

举个简单例子：

    ┌── Router B ──┐

Host ── Router A Router D ── 10.0.0.0/24
└── Router C ──┘
Router A 去 10.0.0.0/24 有两条路径：

A -> B -> D
A -> C -> D
如果这两条路径的 metric 一样，比如 OSPF cost 一样、BGP local-pref/AS path/MED 等比较后也等价，那么 Router A 可以安装两条下一跳：

10.0.0.0/24 via Router B
10.0.0.0/24 via Router C
这就是 ECMP。

ECMP 的作用
主要有两个：

  1. 负载分担

多条链路一起承载流量，提高整体带宽。

100G + 100G ≈ 可承载接近 200G 的总流量
但注意，通常不是单条 TCP 流同时走两条链路，而是不同 flow 被 hash 到不同路径。

  1. 冗余容灾

如果其中一条路径故障，流量可以切到剩余路径上。

ECMP 怎么决定走哪条路径？
大多数设备会做 hash，常见 hash 字段包括：

源 IP
目的 IP
源端口
目的端口
协议号
也就是常说的 五元组 hash。

例如：

Flow 1: 192.168.1.10:12345 -> 8.8.8.8:443 走 Path A
Flow 2: 192.168.1.11:23456 -> 8.8.8.8:443 走 Path B
Flow 3: 192.168.1.12:34567 -> 8.8.8.8:443 走 Path A
这样可以避免同一个 TCP 连接的包乱序。

为什么不是按包轮询？
理论上可以按包分担，但实际很少这么做，因为容易导致：

packet 1 走链路 A
packet 2 走链路 B
packet 3 走链路 A
如果两条链路延迟不同，到达顺序可能变成：

packet 2 先到
packet 1 后到
packet 3 再到
这会造成 TCP 乱序、重传、吞吐下降。

所以实际网络里多是 per-flow ECMP，不是 per-packet ECMP。

和普通路由有什么区别？
普通路由可能是：

10.0.0.0/24 via 192.168.1.1
ECMP 是：

10.0.0.0/24 via 192.168.1.1
10.0.0.0/24 via 192.168.1.2
10.0.0.0/24 via 192.168.1.3
也就是同一个目的前缀，有多个等价 next-hop。

Linux 里的 ECMP 示例
Linux 上可以这样配置：

ip route add 10.10.0.0/16
nexthop via 192.168.1.1 dev eth0 weight 1
nexthop via 192.168.2.1 dev eth1 weight 1
查看：

ip route show 10.10.0.0/16
可能看到类似：

10.10.0.0/16
nexthop via 192.168.1.1 dev eth0 weight 1
nexthop via 192.168.2.1 dev eth1 weight 1
ECMP 和负载均衡的区别
ECMP 可以理解为三层路由层面的负载分担。

它不是应用层负载均衡，比如 Nginx/LVS 那种：

客户端 -> LB -> 后端服务
ECMP 是路由转发层面的：

Router -> 多个 next-hop -> 目标网络
常见使用场景
在数据中心网络里特别常见，例如：

Leaf-Spine 架构
一个 Leaf 到多个 Spine 的路径成本相同，就可以使用 ECMP。

在运营商网络、核心网、Kubernetes CNI、BGP fabric、EVPN/VXLAN 场景里也很常见。

一句话总结：

ECMP 就是同一个目的路由有多条等价路径，设备通过 hash 把不同流量分散到不同路径上，实现带宽利用和冗余。
